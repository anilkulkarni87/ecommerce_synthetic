## Platform

## Users

- **Data & analytics engineers:** Evaluating the 24-table schema, CLI flags, and direct-to-warehouse exporters (DuckDB, Snowflake, Databricks Unity Catalog, BigQuery) before generating datasets locally or in CI.
- **Identity resolution / MDM engineers:** Benchmarking entity-stitching pipelines on realistic decoupled POS (`instore_accounts`, `orders_instore`) vs. digital (`customers`, `orders_online`) records using `identity_ground_truth.parquet`.
- **Data science & ML teams:** Looking for behavioral persona-driven clickstream funnels (`anonymous_id`), fraud anomalies, churn/loyalty, and multi-currency retail datasets.

## Product Purpose

`ecommerce-synth` is an open-source, deterministic, referentially-intact omnichannel synthetic ecommerce data generator (Small to XL, up to 500M+ rows) written in Python + Polars. Its GitHub Pages site serves as the interactive schema explorer, CLI command composer, warehouse exporter guide, and SQL recipe reference.

## Positioning

Unlike toy uniform random generators, `ecommerce-synth` models true decoupled omnichannel retail:
- **Decoupled POS vs. Digital:** `instore_accounts` and `orders_instore` carry `customer_id = NULL`, capturing `phone_number`, `email`, or both, alongside POS-only shoppers, anonymous walk-ins, and `payment_token` card fingerprints.
- **Omnichannel Fulfillment & Attribution:** BOPIS (`fulfillment_type`, `pickup_store_id`), BORIS (`return_channel`, `return_store_id`), guest checkouts (`guest_email`), and persistent clickstream `anonymous_id` device cookies.
- **Warehouse-Scale Streaming & Governance:** Chunked Parquet (`ChunkedParquetWriter`) and zero-file direct streaming (`--stream-to`) into DuckDB, Snowflake, Databricks UC, and BigQuery with 31 PII/financial governance tags.
- **Cross-Channel Ground Truth:** `identity_ground_truth.parquet` scores entity resolution across duplicate digital profiles, temporal PII drift, 5% household sharing, and POS-to-digital links.

## Operating Context

- Static GitHub Pages site deployed from `docs/index.html` via `.github/workflows/pages.yml`.
- Built deterministically by `docs/build_pages.py` reading `config/schema.json`.
- Visitors browse on desktop and mobile while comparing table columns, copying DDL/SQL recipes, or composing CLI commands.

## Capabilities and Constraints

- Must remain a self-contained static `docs/index.html` generated by `docs/build_pages.py` from `config/schema.json` (no Node build step required).
- Must preserve the interactive 24-table schema dictionary (with domain filters, search, DDL dialect switcher, and sample previews), interactive Relationship Map (ERD), Volume Tiers & CLI command builder, Multi-Warehouse Exporters, SQL Recipes, and Behavioral Personas matrix.
- Light or dark theme is not pinned; choose the surface that best serves technical comprehension and visual clarity.

## Evidence on Hand

- `config/schema.json` (22 core tables + 2 optional tables: `customer_consents`, `identity_ground_truth`)
- `src/ecommerce_synth/` generators, exporters, profiler, and CLI
- Live DuckDB / Parquet outputs and `v_omnichannel_sales` / `v_customer_360` SQL views

## Product Principles

1. **Prove the data model immediately:** Show how decoupled POS, digital, clickstream, and fulfillment connect without hiding behind marketing fluff.
2. **Scannable precision for engineers:** Table schemas, CLI flags, and SQL recipes must be effortless to filter, read, and copy.
3. **Zero-friction static delivery:** Everything ships in a single fast static HTML artifact rebuilt from `config/schema.json`.
